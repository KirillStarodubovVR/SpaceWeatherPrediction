# Координаты КА на этапе довыведения

Набор скриптов вычисляет координаты космического аппарата x, y, z на этапе довыведения и после него. Исходные данные:

* **OPM** (CCSDS Orbit Parameter Message): вектор состояния на начальную эпоху;
* **таблица Excel** (лист `all_sats`): средние элементы орбиты на ряд эпох.

| Файл | Назначение |
|---|---|
| `sat_coords.py` | расчёт координат и скоростей в GCRF и ITRF, сверка с таблицей |
| `plot_orbit.py` | 3D-вид Земли с орбитой и КА, трасса на карте |

## Установка и запуск

```bash
pip install numpy scipy pandas openpyxl pyerfa matplotlib

python sat_coords.py --opm R3D21_2026-10-08T12.57.00.027+03.00.opm \
                     --excel all_sats.xlsx --step 60 --out R3D21_xyz.csv

python plot_orbit.py R3D21_xyz.csv --time 2026-10-12T09:00:00Z \
                     --title R3D21 --out earth.png --track track.png
```

Основные параметры `sat_coords.py`:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `--step` | 60 | шаг выдачи координат, с |
| `--scid` | `OBJECT_ID` из OPM | какой КА брать из листа (в листе несколько аппаратов) |
| `--sheet` | первый лист | имя листа Excel |
| `--end-seconds` | последняя строка таблицы | конец расчёта, секунд от эпохи OPM |
| `--absolute` | выкл. | подгонять под абсолютные a, e таблицы (см. шаг 4) |
| `--iters` | 2 | число итераций стрельбы на отрезок |
| `--dut1` | 0 | UT1−UTC, с (влияет только на ITRF) |
| `--j2`, `--re` | оценка по таблице, 6378,137 км | константы поля |
| `-v` | | печатать эквивалентную тягу на каждом отрезке |

Результаты:

* `R3D21_xyz.csv` содержит `time_utc`, `t_s`, а также `x/y/z_gcrf_km`, `vx/vy/vz_gcrf_kms`, `x/y/z_itrf_km`, `vx/vy/vz_itrf_kms`;
* `R3D21_xyz_check.csv` — невязки модели относительно таблицы на каждой её эпохе: Δa, Δe, Δi, ΔΩ.

## Исходные данные и что из них следует

**OPM** содержит вектор состояния r, v в системе GCRF на эпоху t₀ (шкала UTC), а также GM и массу. Это *оскулирующее* состояние: в нём учтены все короткопериодические колебания орбиты.

**Таблица** содержит по каждому КА столбцы `date, ha, hp, inc, raan, dRaanDt, mass`. Разбор данных показал следующее.

* `ha` и `hp` даны в метрах. Большая полуось a = R + (ha + hp)/2 и эксцентриситет e = (ha − hp)/(2a) получаются при R = 6378,137 км.
* `inc` и `raan` даны в радианах, `dRaanDt` — в рад/с.
* Это **средние элементы теории J2**. `dRaanDt` до пятого знака совпадает с формулой
  Ω̇ = −3/2 · n · J2 · (R/p)² · cos i при J2 = 1,08263·10⁻³.
* Наклонение и ДВУ отсчитываются **от истинного экватора даты (система CIRS)**, а не от экватора GCRF. По OPM в GCRF наклонение равно 82,397°, в CIRS — 82,303°, в таблице — 82,299°. Расхождение 0,1° объясняется прецессией земной оси с 2000 года.
* **В таблице нет положения КА на орбите** (аргумента широты или аномалии). Средние элементы задают размер, форму и плоскость орбиты, но не точку на ней. Поэтому положение КА в начальный момент берётся из OPM, а дальше вычисляется интегрированием.

## Алгоритм

### 1. Чтение и подготовка данных
1. Из OPM читаются эпоха, r, v, GM и `OBJECT_ID`.
2. Из таблицы отбираются строки нужного КА (по `scid`, при неудаче — по `scname`).
3. Даты переводятся в секунды от эпохи OPM. Дробная часть секунд хранится отдельно: в таблице бывает 15 и более знаков после запятой.
4. Единицы определяются автоматически (метры или километры, радианы или градусы).
5. Для каждой строки вычисляются a и e.
6. По dRaanDt оценивается J2, использованный при составлении таблицы:
   J2 = −Ω̇ / (3/2 · n · (R/p)² · cos i).

### 2. Переход в систему интегрирования
Вектор состояния из OPM переводится из GCRF в CIRS:

r_CIRS = C · r_GCRF,  где C — матрица `erfa.c2i06a` (модель прецессии-нутации IAU 2006/2000A) на эпоху OPM.

В CIRS ось z направлена на истинный полюс даты. Поэтому возмущение J2 действует вдоль правильной оси, а наклонение и ДВУ непосредственно сравнимы с таблицей. За 10 суток полюс смещается на тысячные доли угловой секунды, так что матрица C принимается постоянной.

### 3. Модель движения
Уравнения движения интегрируются численно методом Рунге–Кутты 8-го порядка (DOP853, относительная точность 10⁻¹¹):

r̈ = −μ r/|r|³ + a_J2(r) + a_T · v/|v|

* **a_J2** — ускорение от второй зональной гармоники:
  a_x = −k·x·(1 − 5z²/r²),  a_y = −k·y·(1 − 5z²/r²),  a_z = −k·z·(3 − 5z²/r²),  где k = 3/2 · J2 · μ · R² / r⁵.
* **a_T** — эквивалентное трансверсальное ускорение (направлено по скорости). Оно заменяет тягу двигателя и торможение атмосферы, о которых у нас нет данных:

  a_T = A + B · cos(u − ω),

  где u — аргумент широты КА, ω — средний аргумент перигея (он медленно поворачивается со скоростью ω̇ от J2).

Почему такая форма. Для околокруговой орбиты уравнения Гаусса дают:
* da/dt = 2 a^{3/2} a_T / √μ. Постоянная часть A меняет большую полуось, а гармоника B за виток на неё в среднем не влияет.
* d|e|/dt = B / v. Гармоника B меняет модуль эксцентриситета, не поворачивая перигей, а A за виток на e в среднем не влияет.

Таким образом A и B независимо управляют a и e.

### 4. Средние элементы модели и калибровка по OPM
Средние элементы модели вычисляются **усреднением оскулирующих элементов за один виток пассивного полёта**. Короткопериодические колебания от J2 периодичны по u, поэтому при усреднении они взаимно уничтожаются.

Определения «среднего» в таблице и в модели немного различаются. В начальной точке получается:
* a: модель 6840,396 км, таблица 6840,366 км (разница 29 м);
* e: модель 3,6·10⁻⁴, таблица 7,2·10⁻⁴.

Если подгонять модель к абсолютным значениям таблицы, её период изменится, и КА уйдёт вдоль орбиты примерно на 4 км за сутки. Поэтому по умолчанию **абсолютный уровень берётся из OPM, а из таблицы берётся только изменение**:

* a_цель(t) = a_табл(t) + (a_модель(t₀) − a_табл(t₀));
* e_цель(t) = e_табл(t) · e_модель(t₀) / e_табл(t₀).

Флаг `--absolute` отключает калибровку.

### 5. Подбор A и B на каждом отрезке (метод стрельбы)
Отрезки — это интервалы между соседними эпохами таблицы. Для отрезка [tₖ, tₖ₊₁]:
1. Начальное приближение:
   * A = (a_цель(tₖ₊₁) − a_ср(tₖ)) / Δt · √μ / (2 a^{3/2});
   * B = v · (e_цель(tₖ₊₁) − e_ср(tₖ)) / Δt.
2. Интегрируем отрезок и вычисляем средние a и e на его конце.
3. Поправляем A и B на невязку и повторяем. Обычно хватает 1–2 итераций до совпадения a с точностью около 0,5 м.
4. На отрезках короче витка (пассивный полёт, строки раз в час) e не подстраивается: там гармоника не успевает усредниться, а e по таблице и так не меняется.

Состояние в конце отрезка становится начальным для следующего, так что траектория непрерывна.

Побочный результат — эквивалентная тяга F ≈ m·|A| (печатается с флагом `-v`). Для R3D21 на участке довыведения она составляет десятки мН в среднем за виток.

### 6. Выдача координат
* **GCRF**: r_GCRF = Cᵀ · r_CIRS — та же система, что в OPM.
* **ITRF**: поворот на угол вращения Земли (ERA, `erfa.era00`, UT1 = UTC + dut1):
  * x' = x cos θ + y sin θ;
  * y' = −x sin θ + y cos θ;
  * z' = z;
  * скорость дополнительно исправляется на член −ω⊕ × r.

  Движение полюса не учитывается (ошибка около 10 м). Если не задан `--dut1`, вдоль экватора добавляется ошибка до ±0,5 км.
* Координаты выдаются с шагом `--step` и дополнительно на всех эпохах таблицы.

### 7. Сверка
На каждой эпохе таблицы средние элементы модели сравниваются с таблицей. Средний ДВУ относится к середине витка усреднения, поэтому с ним сравнивается raan + dRaanDt·T/2. Результаты по тестовым строкам со снимков экрана:

| Элемент | Невязка | Комментарий |
|---|---|---|
| a | < 1 м | подгоняется |
| e | ~10⁻⁷ | подгоняется |
| i | 0,002° постоянно | различие определений среднего |
| Ω | растёт до 0,013° за 10 сут | таблица использует формулу Ω̇ первого порядка, интегрирование учитывает J2 полностью; поперёк орбиты это ≈ 1,6 км |

## Точность и ограничения

* **Радиальная и поперечная составляющие** определены хорошо (единицы км и лучше): размер, форма и плоскость орбиты привязаны к таблице.
* **Положение вдоль орбиты — главная неопределённость.** Оно зависит от того, *когда внутри интервала* работал двигатель, а таблица этого не говорит. Модель «размазывает» тягу равномерно по отрезку. Для оценки: расчёты с калибровкой и без неё (`--absolute`) расходятся на 4 км через сутки и на 39 км через 10 суток. Ошибку того же порядка следует ожидать и от неизвестного распределения тяги.
* **Как уменьшить ошибку до сотен метров** — нужно что-то одно:
  * программа включений двигателя (время и длительность);
  * второй OPM (или любые траекторные измерения) на конечную эпоху, по которому подстраивается фаза.
* Направление перигея после манёвров неизвестно. Модель меняет только модуль e, не поворачивая перигей. После круговизации (e ≈ 10⁻⁵) это перестаёт влиять на результат.
* Из гармоник поля учтена только J2: на ней построена сама таблица. Атмосфера и тяга учтены косвенно, через подгонку a и e.

## Визуализация (`plot_orbit.py`)

```python
from plot_orbit import plot_satellite, plot_ground_track

# 3D: Земля, виток орбиты, КА, вектор скорости, подспутниковая точка
fig, ax = plot_satellite("R3D21_xyz.csv", time="2026-10-12T09:00:00Z",
                         frame="itrf", title="R3D21", out="earth.png")

# трасса на карте
fig, ax = plot_ground_track("R3D21_xyz.csv", time="2026-10-12T09:00:00Z",
                            past_rev=3, future_rev=1, out="track.png")
```

Параметры `plot_satellite`:

| Параметр | Смысл |
|---|---|
| `time` | момент: строка ISO UTC, секунды `t_s` или `None` (последняя точка) |
| `frame` | `itrf` — Земля неподвижна, под КА видна подстилающая поверхность; `gcrf` — инерциальная система, орбита замкнута, материки повёрнуты на момент `time` |
| `past_rev`, `future_rev` | сколько витков показать до момента (сплошной линией) и после него (пунктиром) |
| `elev`, `azim` | угол обзора; по умолчанию камера смотрит прямо на КА |
| `coastline` | путь к GeoJSON с береговой линией, `"auto"` или `None` |
| `ax` | можно передать свою ось `projection="3d"` |

Обе функции возвращают `(fig, ax)`. Части Земли и орбиты, закрытые шаром от наблюдателя, скрываются вручную: matplotlib сам не умеет правильно перекрывать объекты в 3D.

Широта, долгота и высота КА вычисляются над эллипсоидом WGS-84 (`erfa.gc2gd`).

Контуры материков берутся из Natural Earth (`ne_110m_coastline.geojson`, общественное достояние). Файл ищется рядом со скриптом и в текущей папке. Если его нет, он один раз скачивается с GitHub. Без сети Земля рисуется только с координатной сеткой.

Интерактивное окно с вращением мышью: `python plot_orbit.py R3D21_xyz.csv --show`.
